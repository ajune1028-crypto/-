앱 이름은 아직 없다. 이 문서에서는 "앱"이라고 부른다.

## 1. 무엇을 만드나

친구를 링크로 방에 초대해서, 방 안의 모든 것을 실시간으로 같이 하는 앱이다.

- **일상**: 가볍게 친구의 하루를 같이 아는 곳. 들어가기 쉽고 계속 하고 싶어야 한다.
- **창작**: 친구와 같이 무언가를 만드는 곳. 글, 노래, 화이트보드.

성공 기준은 두 단계다. 먼저 친구와 실제로 써 본다. 그다음 스토어에 출시한다.

## 3. 만드는 방식: 비교와 선택

### A. 웹앱 하나 (선택)

브라우저에서 도는 앱을 하나 만든다. 링크를 열면 설치 없이 바로 방에 들어간다. 홈 화면에 추가하면 앱처럼 열린다. 스토어에는 이 웹앱을 앱으로 포장해서 올린다.

- 좋은 점: "링크 = 방"이 그대로 된다. 기기 종류를 가리지 않는다. PC 버전이 따로 필요 없다. 지금 작업 환경에서 만들고 시험할 수 있다.
- 아쉬운 점: 펜과 오디오의 반응 속도가 네이티브 앱보다 조금 느리다. 푸시 알림이 약하다. 스토어 심사에서 포장한 웹앱은 더 꼼꼼히 본다.

### B. Flutter로 앱과 웹을 같이

코드 하나로 안드로이드, 아이폰, 웹을 만든다.

- 좋은 점: 캔버스와 애니메이션 성능이 좋다.
- 아쉬운 점: 웹 버전이 무겁고 한글 입력이 불안정하다. 링크로 들어오는 경험이 느리다. PC에 개발 도구를 설치해 직접 빌드해야 하고, 지금 작업 환경에서는 빌드를 확인할 수 없다.

### C. 안드로이드 네이티브 앱 + 웹 뷰어 따로

- 좋은 점: 안드로이드에서 가장 빠르다.
- 아쉬운 점: 앱과 웹을 두 번 만든다. 아이폰과 아이패드는 세 번째로 또 만든다. "링크만 있으면 어디서든"과 맞지 않는다.

### 선택 이유

A를 고른다. 요구 사항의 중심이 "링크만 있으면 어디서든"이고, 가장 빨리 친구와 써 볼 수 있기 때문이다. 펜과 오디오 반응 속도는 화이트보드 조각에서 다시 측정하고, 부족하면 그 부분만 네이티브로 보강하는 길을 열어 둔다.

기술 선택은 다음과 같다.

- 빌드 도구 없이 표준 웹 기술(HTML, CSS, JavaScript 모듈)만 쓴다. 파일을 그대로 올리면 동작한다.
- 외부 라이브러리 없이 시작한다. 지금 작업 환경은 패키지 설치가 막혀 있어서, 외부 라이브러리를 쓰면 자동 테스트를 돌릴 수 없다.
- 실시간 합치기 규칙(여러 명이 동시에 고쳐도 결과가 같아지는 규칙)은 직접 구현하고 자동 테스트로 검증한다.
- 네트워크 설정에서 패키지 설치를 허용하면 검증된 공개 라이브러리로 바꾸는 선택지가 생긴다. 설정을 바꾼 뒤 새 대화부터 적용된다.

## 4. 어디서 돌리나: 3단계

같은 앱을 세 곳에서 차례로 돌린다. 앱 본체는 그대로 두고, 데이터를 주고받는 부분(전송 계층)만 갈아 끼운다.

| | 1단계: 시험판 | 2단계: 실제 배포 | 3단계: 스토어 앱 |
|---|---|---|---|
| 여는 법 | Claude 안의 페이지 | 공개 주소의 링크 | 스토어에서 설치 |
| 로그인 | Claude 로그인 필요 | 없음 | 없음 |
| 같이 쓰기 | 내 기기끼리 가능. 친구는 Claude 계정으로 편집자 초대가 될 때만 가능 | 링크만 있으면 누구나 | 2단계와 같음 |
| 마이크·카메라 | 직접 못 씀. 파일 가져오기로 대신 | 가능 | 가능 |
| 방 만들기 제한 | 구분 없음 (설치 개념이 없음) | 홈 화면에 추가한 앱에서만 | 앱에서만 |
| 비밀번호 | 화면상의 문. 진짜 보안은 아님 | 서버가 검사 | 2단계와 같음 |
| 필요한 것 | 없음 | 무료 계정 2개, 약 15분 | 스토어 개발자 등록(유료) |

### 1단계: 시험판

만든 것을 Claude 안의 페이지로 올린다. 폰과 다른 기기(태블릿, PC)에서 같은 페이지를 열면 실시간 동작을 확인할 수 있다.

시험판의 한계는 페이지가 돌아가는 환경에서 온다.

- 페이지 안에서 마이크와 카메라를 켤 수 없다. 사진과 녹음은 "파일 선택"으로 가져온다. 폰에서는 파일 선택이 카메라 앱과 녹음 앱을 열어 준다.
- Claude에 로그인한 사람만 볼 수 있다. 친구가 링크만으로 들어오지 못한다.
- 홈 화면에 앱으로 추가할 수 없다.

### 2단계: 실제 배포

공개 주소에 올리고 실시간 서버를 붙인다. 여기서 "링크 = 방", 로그인 없음, 마이크 녹음, 비밀번호 검사가 진짜로 된다.

사용자가 할 일은 무료 계정 2개를 만드는 것이다.

- **GitHub**: 앱 파일을 올려 두는 곳. 공개 주소가 여기서 나온다.
- **Supabase**: 실시간 전달, 데이터 저장, 사진·녹음 파일 저장.

Supabase를 고른 이유는 무료 요금제에 파일 저장이 포함되고 카드 등록이 필요 없기 때문이다. Firebase는 2026년 2월부터 파일 저장에 결제 수단을 연결한 요금제가 필요하다. 무료 Supabase 프로젝트는 일주일 동안 쓰지 않으면 일시정지되고, 관리 화면에서 다시 켜야 한다.

2단계는 별도 설계 문서로 다룬다. 계정이 준비되면 시작한다. 노래 만들기의 녹음 버튼은 2단계부터 쓸 수 있다.

### 3단계: 스토어 앱

웹앱을 앱으로 포장해 플레이스토어에 먼저 올리고, 앱스토어는 그다음이다. 별도 설계 문서로 다룬다.

## 5. 조각과 순서

조각마다 설계 → 구현 계획 → 구현을 따로 돈다.

| 순서 | 조각 | 내용 | 설계 문서 |
|---|---|---|---|
| 1 | 바탕 + 일상 텍스트 방 | 홈, 방, 초대, 실시간 전달, 디자인, 같이 쓰는 글 | 작성함 |
| 2 | 노래 만들기 방 | 녹음 → 피아노 음 변환, 타임라인 편집 | 작성함 |
| 2단계 | 실제 배포 | 공개 주소, 실시간 서버, 비밀번호 검사, 홈 화면 앱 | 계정 준비 후 |
| 3 | 일상 사진 방, 통합 방 | 시간대별 사진·3초 영상, 홈 카메라 | 나중 |
| 4 | 창작 글쓰기 방 | A4/스크롤 문서, 스티커, 브러쉬 | 나중 |
| 5 | 화이트보드 방 | 큰 캔버스에 전부 통합, 재생 순서 잇기 | 나중 |
| 3단계 | 스토어 출시 | 플레이스토어, 앱스토어 | 나중 |

실제 배포는 조각 1 이후 언제든 끼워 넣을 수 있다. 녹음 버튼은 실제 배포가 되어야 쓸 수 있으므로, 조각 2와 비슷한 시기에 하는 것이 좋다.

## 6. 모든 방에 공통인 규칙

### 6.1 사람과 개인 식별 코드

- 로그인은 없다. 방마다 "사람"이 있고, 사람은 별명과 색을 가진다.
- 방에 처음 들어올 때 별명을 정한다. 색은 겹치지 않게 자동으로 정해지고 바꿀 수 있다.
- 사람마다 개인 식별 코드를 정할 수 있다. 숫자 5자리다. 앱에서 들어온 사람도, 링크로 들어온 사람도 정할 수 있다.
- 다른 기기에서 같은 방 링크로 들어와 내 이름을 고르고 코드를 입력하면 같은 사람으로 들어온다. 색이 그대로이고, 그 기기에서 쓴 글과 올린 사진도 내 것으로 표시된다.
- 코드를 정하지 않은 사람은 다른 기기에서 같은 사람으로 들어올 수 없다. 새 사람으로 들어오게 된다.
- 기기는 방마다 "내가 누구인지"를 기억한다. 앱은 마지막에 쓴 별명과 코드를 기억했다가 새 방에 들어갈 때 미리 채워 준다.
- 숫자 5자리는 친구끼리 서로를 구분하기 위한 것이다. 강한 보안 수단은 아니다. 5번 틀리면 30초 기다리게 한다. 2단계에서는 서버가 횟수를 제한한다.
- 브라우저 데이터를 지우면 방 목록이 사라진다. 방 링크와 코드가 있으면 다시 같은 사람으로 들어올 수 있다.

### 6.2 방과 링크

- 방 주소에는 길고 무작위인 코드가 들어 있다. 이 코드를 모르면 방을 찾을 수 없다.
- 방을 만든 기기가 방장이다. 방장은 방 이름과 비밀번호를 바꾸고 방을 지울 수 있다.
- 홈의 방 목록은 이 기기가 만들었거나 들어간 방이다.
- "방 나가기"는 내 목록에서만 뺀다. 방은 남는다.

### 6.3 방 만들기

- 2단계부터: 설치한 앱(홈 화면에 추가한 것 포함)에서만 + 버튼이 보인다. 브라우저에서 링크로 온 사람은 참여만 한다.
- 시험판: 설치 개념이 없어서 누구나 만들 수 있다.

### 6.4 방 비밀번호

- 방마다 비밀번호가 하나 있다. 방장이 켜고, 끄고, 바꾼다. 바꾸면 그 순간부터 새 비밀번호가 적용된다.
- 방에 처음 들어오는 기기는 비밀번호를 입력한다. 설치한 앱에서 링크로 방을 추가할 때도, 브라우저에서 링크로 들어올 때도 같다.
- 통과한 기기는 기억해서 다시 묻지 않는다. 앱에서는 그 방이 홈의 방 목록에 추가된다.
- 일상 방은 기본이 "비밀번호 없음"이다. 창작 방은 만들 때 비밀번호를 정하고, 끌 수 있다. (가정)
- 비밀번호를 바꿔도 이미 들어와 있는 사람은 그대로 둔다. (가정)

### 6.5 잠금

- 내용의 일부를 잠가서 아무도 고치지 못하게 한다. 잠근 사람과 방장만 풀 수 있다.
- 잠금 대상은 방마다 다르다. 텍스트 방은 글 구간, 노래 방은 클립이다.

### 6.6 실행취소와 다시실행

- 모든 방에 버튼 두 개가 있다.
- 내가 한 것만 되돌린다. 친구가 한 것은 건드리지 않는다.

### 6.7 연결

- 연결이 끊겨도 계속 쓸 수 있다. 다시 연결되면 자동으로 합쳐진다.
- 연결 상태를 작은 점으로 보여 준다.

## 7. 디자인 언어

참고 이미지에서 가져온 규칙이다.

- **그레이니 그라데이션**: 크게 번진 색 덩어리 위에 고운 필름 입자를 얹는다.
- **다크**: 검정에 가까운 남색 바탕. 청록, 파랑, 살구색이 번진다. 글자는 흰색.
- **라이트**: 거의 흰 바탕에 옅은 하늘색이나 연보라가 번진다. 카드는 둥근 모서리에 파랑에서 남보라로 이어지는 가는 테두리.
- **홈의 두 색**: 일상은 연한 노랑과 주황, 창작은 연보라.
- **절제**: 화면에 보이는 버튼을 최소로 한다. 필요한 순간에만 도구가 나타난다.
- **가독성**: 본문 글자는 배경과의 명암비 4.5:1 이상. 사진 배경 위에서는 글 뒤에 반투명 막을 깔아 기준을 지킨다. 화면 캡처로 자동 검사한다.
- **움직임**: 짧고 부드럽게. 기기의 "움직임 줄이기" 설정을 따른다.
- **테마**: 라이트, 다크, 기기 설정 따르기.
- **글라스 (11월 13일 추가, "퍼런 애플 글라스")**: 내용은 또렷하게, 그 위에 뜨는 것들이 유리다. 글 쓰는 종이는 거의 불투명(라이트 92%, 다크 90%)해서 여덟 색이 모두 4.5:1을 지킨다. 위쪽 막대, 도구 막대, + 버튼, 알약 버튼, 홈의 방 카드, 아래에서 올라오는 시트는 파란 기가 도는 반투명 유리(뒤를 흐리게, 밝은 테두리)다. 주요 버튼과 스위치는 파랑. 홈의 두 색은 그대로 두고 하늘색이 양쪽 아래에 깔린다.
- **색 필드 위의 글자**: 종이나 시트가 아니라 색 필드에 바로 놓이는 보조 글자는 더 진한 톤(--soft)을 쓴다. 필드의 가장 진한 곳에서도 4.5:1.

## 9. 가정한 것과 확인이 필요한 것

사용자가 "알아서 할 건 알아서"라고 해서 아래는 내가 정했다. 틀린 것만 고치면 된다.

| # | 가정 | 바뀌면 영향받는 곳 |
|---|---|---|
| 1 | 개인 식별 코드는 방마다 따로 정한다. 앱이 마지막 코드를 미리 채워 준다 | 입장 화면 |
| 2 | 일상 방은 기본이 비밀번호 없음, 창작 방은 기본이 있음 | 방 만들기 화면 |

| 5 | 잠금은 잠근 사람과 방장만 푼다 | 모든 방 |
| 6 | "밝은 버전, 안 밝은 버전"은 피아노 음색(밝게/부드럽게)이다 | 노래 방 |

사용자만 할 수 있는 일은 하나다. 2단계에서 GitHub와 Supabase 무료 계정을 만드는 것이다. 급하지 않다.

### 만들면서 달라진 것 (11월 12~13일, 조각 1의 1차)

- **11월 13일의 고장과 원인**: 시험판에서 방이 만들어지지 않았다. 글 쓰는 칸과 입력칸이 같은 클래스 이름(`input`)을 써서, 글 쓰는 칸의 규칙(투명, 화면을 덮음)이 모든 입력칸에 걸렸다. 입력칸이 보이지 않게 화면을 덮어 버튼 대신 눌렸다. 검사 도구가 화면을 실제로 누르지 않고 스크립트로 눌러서 놓쳤다. 지금은 모든 검사가 요소의 한가운데를 실제로 누르고, 무엇이 가리고 있으면 그 이름을 대며 실패한다. 고친 뒤 실제 시험판 저장소에 방이 만들어진 것을 확인했다(11월 13일 23:19).
- **초대**: 방 위쪽의 사람+ 버튼과, 방을 만든 직후 한 번 뜨는 시트. 링크는 "페이지 주소 + #r-방코드".
- **시험판의 한계 (Claude 쪽 규칙)**: 글을 쓸 수 있는 사람은 페이지 주인과, 이메일로 '편집자' 초대를 받은 사람뿐이다. 공개 링크로 온 사람은 읽기만 한다. 누구나 링크로 들어와 같이 쓰는 것은 2단계(실제 주소)에서 된다.
- **이 기기에만 있는 방**: 공용 저장소가 방을 받지 않으면(거절, 무응답) 그 기기에만 방을 만들고, 홈과 방에 그렇게 적는다. 초대 링크는 주지 않는다.
- **연결 진단**: 홈의 설정과 방 설정에 전송 방식, 저장소, 실시간 채널, 마지막 오류, 연결 기록이 보인다.
- **폼 요소를 쓰지 않음**: 버튼의 누름과 Enter 키로 처리한다. 틀 안의 페이지는 폼 제출 이벤트를 못 받을 수 있다.
- **화면 이동**: 주소(#)가 바뀌기를 기다리지 않고 화면을 바로 바꾼다.
- 그 밖의 세부 결정 전체: `docs/superpowers/plans/2026-11-12-text-room-phase1-rulings.md`

## 11. 방향 점검

사용자가 "방향과 본질이 맞는지, 내가 한 말이 다 들어맞는지 계속 확인하라"고 했다. 조각을 끝낼 때마다 이 절을 다시 본다.

### 본질

원문에서 반복되는 말은 네 가지다.

| 본질 | 지금 설계가 지키는 방식 | 아직 못 지키는 것 |
|---|---|---|
| 실시간으로 같이 | 모든 변경이 기록 단위로 즉시 전달되고 합쳐진다. 연결이 끊겨도 쓴 것이 남는다 | 시험판은 친구가 들어오지 못한다. 2단계에서 해결 |
| 쉽고 접근성 좋게 | 로그인 없음. 링크가 곧 방. 설치 없이 열림 | 시험판은 Claude 로그인이 필요하다. 2단계에서 해결 |
| 단순하고 절제되고 예쁘게 | 평소에는 내용만 보이고, 도구는 필요한 순간에만 나온다. 그레이니 그라데이션 | 화면 캡처로 매번 확인한다 |
| 같이 만드는 창작 | 목소리만으로 시작하는 노래 만들기. 같은 문서를 같이 고침 | 녹음 버튼은 2단계부터 |

### 가장 큰 어긋남

"링크만 있으면 어디서든"과 녹음은 시험판에서 되지 않는다. 시험판은 화면과 동작을 빨리 확인하기 위한 것이고, 본질은 2단계 실제 배포에서 채워진다. 2단계에는 사용자의 계정이 필요해서 사용자가 돌아온 뒤에 한다. 그 전에 할 수 있는 준비(전송 계층의 경계, 설정 안내)는 미리 해 둔다.

### 말한 것과 설계의 대조

8절의 목록이 대조표다. 조각이 끝날 때마다 해당 항목을 체크하고, 다르게 만든 것은 9절에 이유와 함께 적는다.

## 12. 진행 방식

- 2026-11-10: 사용자가 "알아서 할 건 알아서"라고 했다. 남은 질문을 가정으로 정했다.

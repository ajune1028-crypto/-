# 조각 2 설계: 노래 만들기 방

- 작성일: 2026-11-10
- 상태: 검토 대기
- 관련 문서: `2026-11-10-app-overview-design.md` (전체 결정, 공통 규칙), `2026-11-10-foundation-text-room-design.md` (바탕, 전송 계층)
- 먼저 필요한 것: 조각 1의 1차 (홈, 방, 실시간 전달)

## 1. 목표

흥얼거린 소리를 같은 박자의 피아노 음으로 바꾼다. 그렇게 만든 클립을 친구와 같이 쌓고, 자르고, 옮겨서 노래를 만든다. 악기를 못 다뤄도 목소리만으로 시작할 수 있어야 한다.

## 2. 범위

세 번에 나눠 만든다. 구현 계획도 차수마다 따로 쓴다.

**0차: 음 인식 실험**

- 목소리에서 음을 얼마나 정확히 뽑는지 수치로 확인한다.
- 결과는 "이 방식으로 간다" 또는 "이렇게 고쳐야 한다"는 판단이다. 실험 코드는 버리고, 검증된 방식만 1차로 가져간다.

**1차: 혼자 쓰는 노래 방**

- 소리 넣기: 녹음 버튼과 파일 가져오기. 마이크를 쓸 수 없는 곳에서는 가져오기만 보인다. 시험판이 그렇다
- 음 인식과 피아노 변환
- 타임라인: 시간 바, 줄, 클립
- 재생, 처음으로
- 원본/피아노 전환, 피아노 음색 2가지
- 클립 조작: 복사, 붙여넣기, 음소거, 분할, 삭제, 옮기기
- 실행취소, 다시실행

**2차: 같이 쓰기**

- 클립 조작이 실시간으로 서로에게 반영
- 접속 표시 (누가 어떤 클립을 잡고 있는지, 누가 녹음 중인지)
- 클립 잠금

**이 조각에서 하지 않는 것**

- 화이트보드의 재생 순서 잇기, 노래 잇기 모드, 순서 저장 칸 (조각 5)
- 인식된 음을 손으로 고치기
- 메트로놈, 박자에 맞춰 음 당기기
- 피아노 외의 악기
- 여러 기기에서 동시에 같은 소리 듣기
- 완성한 노래를 오디오 파일로 내보내기

## 3. 화면

폰 세로 기준이다. 타임라인은 가로로 길어서 좌우로 넘겨 본다.

- **위쪽 줄**: 뒤로, 방 이름, 접속 중인 사람의 색 점, 설정. 오른쪽 위에 **[원본 | 피아노]** 전환.
- **시간 바**: 초 단위 눈금. 항상 타임라인 위에 붙어 있다.
- **타임라인**: 가로가 시간, 세로가 줄이다. 클립은 높이가 같은 직사각형이고 길이가 곧 시간이다. 재생 위치를 나타내는 세로선이 있다.
- **아래쪽 줄**: 처음으로, 재생/멈춤, 녹음, 실행취소, 다시실행.

클립의 모습은 다음과 같다.

| 상태 | 모습 |
|---|---|
| 원본 듣기 | 소리 크기를 따라 그린 파형 |
| 피아노 듣기 | 음 막대. 높은 음은 위, 낮은 음은 아래 |
| 색 | 만든 사람의 색을 연하게 |
| 음소거 | 흐리게, 귀에 사선이 그어진 표시 |
| 잠금 | 작은 자물쇠 |
| 선택됨 | 테두리 강조 |
| 음을 찾지 못함 | 피아노 듣기에서 점선 테두리의 빈 클립 |

방이 비어 있으면 가운데에 한 줄 안내만 보인다.

## 4. 조작

### 4.1 재생 위치

- 시간 바를 누르면 재생 위치가 그 시간으로 간다. 끌면 따라 움직인다.
- 타임라인의 빈 곳을 누르면 재생 위치가 그곳으로 가고, 그 줄이 "선택된 줄"이 된다. 녹음과 붙여넣기는 선택된 줄에 놓인다.
- "처음으로"는 재생 위치를 0초로 보낸다.

### 4.2 재생

- 재생 위치부터 모든 줄의 클립이 동시에 재생된다. 음소거된 클립은 빠진다.
- 마지막 클립이 끝나면 멈춘다.
- 재생 중에는 화면이 재생 위치를 따라간다.

### 4.3 소리 넣기

- 녹음을 누르면 선택된 줄의 재생 위치에서 녹음이 시작된다.
- 녹음하는 동안 빨간 클립이 오른쪽으로 자라난다. 다른 클립은 같이 재생된다. 처음 한 번 "이어폰을 쓰면 다른 소리가 섞이지 않아요"를 알려 준다.
- 다시 누르면 끝난다. 그 자리에 클립이 생기고, 바로 음 인식이 돌아 피아노 음이 준비된다.
- 한 번에 3분까지 녹음한다.
- 마이크를 쓸 수 없는 환경에서는 녹음 버튼 자리에 "소리 가져오기"가 있다. 시험판이 그렇다. 폰의 녹음 앱이나 저장된 파일에서 가져오고, 나머지 처리는 같다.
- "소리 가져오기"는 설정 메뉴에도 항상 있다.

### 4.4 클립 메뉴

클립을 한 번 누르면 선택되고, 위에 작은 메뉴가 뜬다.

| 메뉴 | 동작 |
|---|---|
| 복사 | 이 클립을 기억한다 |
| 붙여넣기 | 기억한 클립을 선택된 줄의 재생 위치에 놓는다 |
| 음소거 | 이 클립을 재생에서 뺀다. 다시 누르면 돌아온다 |
| 분할 | 재생 위치에서 클립을 둘로 자른다. 재생 위치가 클립 안에 있을 때만 켜진다 |
| 잠금 | 옮기기, 분할, 삭제를 막는다 (2차) |
| 삭제 | 클립을 지운다 |

분할은 원본 소리를 건드리지 않는다. 두 클립이 같은 소리의 앞부분과 뒷부분을 가리킬 뿐이다. 복사한 클립도 같은 소리를 가리킨다.

### 4.5 옮기기

- 클립을 꾹 눌렀다가 끌면 옮겨진다. 좌우는 시간, 위아래는 줄이다.
- 꾹 누르지 않고 끌면 타임라인이 넘어간다.

### 4.6 줄

- 줄의 수는 정해져 있지 않다. 맨 아래에 항상 빈 줄이 하나 있고, 거기에 클립을 놓으면 그 아래에 새 빈 줄이 생긴다.
- 클립은 어느 줄에나 놓을 수 있다.
- 한 줄에서 두 클립이 겹칠 수 없다. 놓으려는 자리가 겹치면 가장 가까운 아래 빈 줄로 내려간다.
- 줄은 16개까지, 클립은 방 하나에 200개까지다.

### 4.7 확대와 축소

- 두 손가락으로 벌리고 오므려서 가로 길이를 조절한다.

### 4.8 원본과 피아노

- 오른쪽 위의 전환으로 듣는 방식을 바꾼다. 기본은 피아노다.
- 전환하면 클립의 모습도 파형과 음 막대 사이에서 바뀐다.
- 이 전환은 기기마다 따로다. 내가 바꿔도 친구 화면은 바뀌지 않는다.
- 설정에서 피아노 음색을 "밝게"와 "부드럽게" 중에 고른다.

### 4.9 실행취소와 다시실행

- 내가 한 클립 조작만 되돌린다. 넣기, 옮기기, 분할, 붙여넣기, 음소거, 삭제, 잠금이 대상이다.

## 5. 음 인식과 피아노 변환

### 5.1 처리 순서

1. 소리를 한 채널로 합치고 분석용으로 낮춘다(16 kHz).
2. 0.01초마다 음높이를 잰다. 사람 목소리 범위(약 65~1,050 Hz)만 본다. 소리가 너무 작거나 음이 불분명한 구간은 "음 없음"으로 둔다.
3. 튀는 값을 걸러 낸다. 한 옥타브씩 잘못 튄 짧은 구간은 주변에 맞춰 바로잡는다.
4. 음높이 곡선을 음표로 묶는다.
   - 음높이가 반음의 60% 넘게 벗어난 채로 0.06초 이상 이어지면 새 음이다.
   - 소리 크기가 뚝 떨어졌다가 다시 커지면 새 음이다.
   - 목소리의 떨림(비브라토)은 한 음으로 본다.
   - 0.08초보다 짧은 음은 옆 음에 합치거나 버린다.
5. 각 음의 높이는 그 구간의 가운데 값을 가장 가까운 반음으로 맞춘다.
6. 음의 시작과 길이는 부른 그대로 둔다. 박자에 맞춰 당기거나 밀지 않는다.
7. 음의 세기는 그 구간의 소리 크기에서 가져온다.

위 숫자는 출발점이다. 0차 실험에서 조정한다.

### 5.2 피아노 소리

- 녹음된 피아노 소리를 쓰지 않고, 앱이 피아노 느낌의 소리를 직접 만들어 낸다. 진짜 피아노와 똑같지는 않다.
- "밝게"는 또렷하고 높은 배음이 많은 소리, "부드럽게"는 둥글고 차분한 소리다.
- 나중에 진짜 피아노 녹음으로 바꿀 수 있게 소리 내는 부분을 따로 둔다.

### 5.3 품질 목표

| 시험 | 기준 |
|---|---|
| 합성 시험음: 고정음, 계단, 떨림, 미끄러짐, 잡음 섞임 | 음 높이 전부 일치. 시작 시점 오차 0.03초 이내 |
| 실제 허밍: 아는 노래를 흥얼거린 녹음 3~5개 | 음의 90% 이상 일치. 없는 음이 10초에 1개 이하 |

실제 허밍은 음정의 간격으로 채점한다. 사람마다 시작 음이 달라도 "도에서 솔로 올라갔는지"는 같기 때문이다.

### 5.4 잘 되는 것과 안 되는 것

- 잘 됨: "라라라"나 허밍처럼 한 번에 한 음씩 또렷하게 부른 소리.
- 덜 됨: 가사가 있는 노래. 자음에서 음이 끊길 수 있다.
- 안 됨: 여러 음이 동시에 나는 소리, 시끄러운 곳, 속삭임.
- 음을 하나도 찾지 못하면 클립은 그대로 만들고 "음을 찾지 못했어요. 원본으로 들을 수 있어요"를 보여 준다.

### 5.5 0차 실험

- 합성 시험음은 직접 만든다. 정답을 정확히 알 수 있다.
- 실제 허밍은 사용자가 보내 주는 녹음을 쓴다. 동요처럼 음을 아는 노래면 된다. 없으면 합성 시험음만으로 진행하고, 허밍 채점은 녹음을 받았을 때 한다.
- 기준에 못 미치면 5.1의 숫자를 조정하거나 음높이 재는 방식을 바꾼다. 그 결과를 이 문서에 반영한 뒤 1차를 시작한다.

## 6. 구조

### 6.1 단위와 경계

| 단위 | 하는 일 | 의존하는 것 |
|---|---|---|
| `audio/pitch` | 소리 → 음높이 곡선. 순수 계산 | 없음 |
| `audio/notes` | 음높이 곡선 → 음표 목록. 순수 계산 | 없음 |
| `audio/peaks` | 소리 → 파형을 그릴 요약 값 | 없음 |
| `audio/piano` | 음표 → 피아노 소리. 음색 2가지 | 없음 |
| `audio/engine` | 재생 위치, 재생·멈춤, 클립과 음표를 제때 울리기 | `audio/piano` |
| `audio/recorder` | 마이크 녹음, 지연 보정. 마이크를 쓸 수 있는지 확인 | 없음 |
| `core/song` | 노래 문서: 소리, 클립, 변경 적용, 겹침 해소 | 없음 |
| `ui/song-room` | 노래 방 화면: 시간 바, 타임라인, 클립 메뉴, 끌기 | `core/song`, `audio/engine`, `sync/session`, `core/undo` |

`sync/*`, `identity`, `ui/theme`, `ui/room-shell`, `core/undo`는 조각 1의 것을 그대로 쓴다. `audio/*`는 화이트보드(조각 5)에서 다시 쓴다.

### 6.2 데이터 모델

```
노래 (Song)     id = 방 id
  sources       소리. 한번 만들어지면 바뀌지 않는다
                { id, blob(원본 파일 id), analysis(분석 파일 id), duration, author, createdAt }
  clips         클립
                { id, source(소리 id), row(줄 번호), start(초), offset(초), length(초),
                  muted, locked, author, removes }

분석 파일       { peaks: 파형 요약, notes: [{ t(시작, 초), d(길이, 초), pitch(반음 번호), v(세기) }] }
```

- 클립은 소리의 `offset`부터 `length`만큼을 타임라인의 `start`에 놓는다.
- 분할: 원래 클립의 `length`를 줄이고, 뒷부분을 가리키는 새 클립을 만든다.
- 복사·붙여넣기: 같은 `source`를 가리키는 새 클립을 만든다.
- 음표는 소리와 함께 다니는 작은 데이터다. 그래서 원본 파일이 아직 도착하지 않은 기기에서도 피아노로는 바로 들을 수 있다.

### 6.3 합치기 규칙

조각 1과 같은 방식이다. 모든 변경은 작은 기록 하나이고, 어떤 순서로 받아도 결과가 같다.

- 소리와 클립의 추가는 항상 남는다.
- 클립의 항목(`row`, `start`, `length`, `muted`, `locked`)은 항목마다 나중에 바꾼 값이 이긴다.
- 삭제와 되살리기는 조각 1의 `removes` 규칙을 쓴다.
- 두 사람이 같은 순간에 같은 자리에 클립을 놓아 겹치면, `id`가 큰 클립이 한 줄 아래에 보인다. 모든 기기에서 같은 규칙으로 계산한다.
- 두 사람이 같은 순간에 같은 클립을 분할하면 뒷부분이 두 개 생길 수 있다. 드문 일이고, 하나를 지우면 된다.

### 6.4 재생

- 소리는 브라우저의 오디오 엔진으로 낸다. 클립과 음표는 오디오 엔진의 시계에 맞춰 조금 앞서 예약한다. 화면이 잠깐 버벅여도 소리의 박자는 흔들리지 않는다.
- 원본 듣기: 클립이 가리키는 구간의 소리를 재생한다.
- 피아노 듣기: 클립 구간 안에 있는 음표만 울린다. 구간 경계에 걸친 음은 잘라서 울린다.
- 브라우저는 사용자가 화면을 누르기 전에는 소리를 내지 못하게 막는다. 첫 재생 버튼에서 오디오를 켠다.

### 6.5 녹음과 지연 보정

- 녹음할 때 브라우저의 소리 다듬기(울림 제거, 잡음 제거, 자동 음량)를 끈다. 노래에는 방해가 된다.
- 폰은 소리를 내보내고 받아들이는 데 시간이 걸린다. 그만큼 녹음이 늦게 놓이므로, 기기가 알려 주는 지연 값만큼 클립을 앞으로 당긴다.
- 자동 보정이 맞지 않는 기기를 위해 설정에 "싱크 보정" 조절 막대를 둔다.
- 녹음 기능은 1차에서 만들고 가짜 마이크로 자동 테스트한다. 실제 폰에서의 지연 값은 마이크를 쓸 수 있는 2단계에서 확인하고 조정한다.

### 6.6 파일

- 원본 소리와 분석 파일은 전송 계층의 파일 저장으로 올린다.
- 받은 파일은 기기에 보관해서 다음에는 다시 받지 않는다.
- 녹음은 모든 기기에서 재생되는 형식으로 저장한다. 형식의 호환은 2단계 설계에서 실제 기기로 확인한다.
- 시험판의 파일 저장은 오디오 형식을 직접 받지 않는다. 그래서 시험판 전송 구현은 오디오를 받아 주는 형식으로 감싸서 올리고, 받을 때 푼다. 앱 본체는 이 차이를 모른다.

## 7. 같이 쓰기 (2차)

- 한쪽의 클립 조작은 1초 안에 다른 쪽 화면에 보인다.
- 친구가 선택했거나 끌고 있는 클립에는 그 친구 색의 테두리가 보인다.
- 친구가 녹음 중이면 그 줄에 자라나는 자리 표시와 별명이 보인다.
- 한쪽이 넣은 소리는 다른 쪽에서 피아노로 바로 들을 수 있다. 원본은 파일을 다 받은 뒤에 들을 수 있고, 그 전에는 클립에 "받는 중"이 보인다.
- 재생은 각자 한다. 내가 재생을 눌러도 친구 기기에서는 소리가 나지 않는다.
- 잠긴 클립은 옮기기, 분할, 삭제가 막힌다. 잠근 사람과 방장만 푼다. 음소거와 복사는 된다.

## 8. 오류와 예외

| 상황 | 동작 |
|---|---|
| 마이크 권한을 거부함 | 이유를 알려 주고 "소리 가져오기"를 대신 제안한다 |
| 가져온 파일을 읽을 수 없음 | "이 파일은 읽을 수 없어요"를 보여 주고 취소한다 |
| 3분이 넘는 소리 | 앞의 3분만 쓸지 묻는다 |
| 음을 찾지 못함 | 클립은 만든다. 피아노 듣기에서는 점선의 빈 클립으로 보인다 |
| 파일 올리기 실패 | 내 기기에서는 정상 동작한다. 클립에 "올리는 중 / 다시 시도"를 보여 준다. 친구는 피아노로만 듣는다 |
| 친구가 넣은 원본을 받지 못함 | 피아노로 재생하고 클립에 "원본 없음"을 보여 준다 |
| 연결이 끊김 | 계속 편집할 수 있다. 다시 연결되면 합쳐진다 |
| 줄 16개, 클립 200개 한도 | 한도에 닿았다고 알려 주고 새로 놓지 않는다 |
| 저장 공간이 가득 참 | 알려 주고, 새 소리는 내 기기에만 둔다 |
| 재생 중 탭이 뒤로 감 | 재생을 멈춘다 |

## 9. 테스트

**자동 테스트**

- 음 인식: 합성 시험음 묶음을 넣고 5.3의 기준으로 채점한다.
- 음표 묶기: 음높이 곡선을 직접 만들어 넣고 음표가 기대와 같은지 본다. 떨림, 미끄러짐, 짧은 끊김, 옥타브 튐을 포함한다.
- 노래 문서: 분할, 복사, 붙여넣기, 옮기기, 겹침 해소, 음소거, 삭제, 되돌리기.
- 합치기: 기기 3대가 무작위로 조작하고 무작위 순서로 전달해도 결과가 같다.
- 재생 예약: 소리를 실제로 내지 않고 계산만 하는 방식으로, 정해진 시각에 정해진 음이 울리는지 본다.
- 녹음: 헤드리스 크롬에 가짜 마이크(시험용 소리 파일)를 물리고, 녹음에서 클립 생성과 음 인식까지 이어지는지 본다.
- 두 화면 시나리오: 한쪽의 조작이 다른 쪽에 보인다. 한쪽이 잠근 클립을 다른 쪽이 옮길 수 없다.

**수동 확인**

- 폰에서 허밍을 넣고 피아노로 들어 본다. 원본과 번갈아 듣는다.
- 클립 두 개를 다른 줄에 겹쳐 놓고 박자가 맞는지 듣는다.
- 2단계 이후: 녹음 버튼, 지연 보정, 안드로이드와 아이폰 사이의 재생.

## 10. 완료 기준

**0차**

- 합성 시험음이 5.3의 기준을 통과한다.
- 실제 허밍을 받았다면 그 기준도 통과하거나, 못 미치는 이유와 고칠 방법이 정리되어 있다.

**1차**

- 허밍을 넣으면 클립이 생기고, 재생하면 같은 박자의 피아노 음이 들린다.
- 오른쪽 위에서 원본과 피아노를 오갈 수 있다.
- 시간 바를 눌러 원하는 시간으로 갈 수 있다.
- 클립을 여러 줄에 쌓으면 동시에 들린다.
- 복사, 붙여넣기, 음소거, 분할, 삭제, 옮기기, 실행취소가 동작한다.
- 자동 테스트가 전부 통과한다.

**2차**

- 두 기기에서 같은 방을 열면 한쪽의 클립 조작이 1초 안에 다른 쪽에 보인다.
- 한쪽이 넣은 소리를 다른 쪽이 피아노로 바로 듣고, 원본도 받아서 듣는다.
- 잠긴 클립은 다른 사람이 옮기거나 자르거나 지울 수 없다.

## 11. 가정과 위험

**가정** (전체 목록은 개요 문서 9절)

- "밝은 버전, 안 밝은 버전"은 피아노 음색이다.
- 원본/피아노 전환은 기기마다 따로다.
- 재생은 각자 기기에서 한다.
- 박자에 맞춰 음을 당기지 않는다. 부른 그대로 둔다.
- 원문의 "앞으로 가는" 버튼은 재생 위치를 처음으로 보내는 버튼이다.
- 한 번 녹음은 3분까지, 줄은 16개까지, 클립은 방 하나에 200개까지다.

**위험과 대비**

| 위험 | 대비 |
|---|---|
| 실제 목소리에서 음 인식이 부정확함 | 0차 실험과 수치 기준. 방식을 바꿀 여지를 둠. 원본 듣기는 항상 가능 |
| 폰 브라우저의 소리 지연으로 겹쳐 녹음한 박자가 어긋남 | 자동 보정과 "싱크 보정" 막대. 클립을 손으로 옮길 수 있음 |
| 기기마다 재생되는 오디오 형식이 다름 | 2단계 설계에서 안드로이드와 아이폰으로 확인 |
| 직접 만든 피아노 소리가 기대보다 가벼움 | 소리 내는 부분을 따로 두어 진짜 피아노 녹음으로 교체 가능 |
| 시험판에서 녹음 버튼을 쓸 수 없음 | "소리 가져오기"로 대신. 녹음 버튼은 2단계부터 보임 |
